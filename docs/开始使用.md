# 本地开始使用

这是一版可以运行的旅行客服/运营政策检索工作台：中文界面、英文 README，尚未接入 LLM。选用 Peach 官方公开资料，覆盖一般行李和个人原因退改政策。无需 API 密钥，也不会产生模型调用费用。

v0.2 新增“客服协助代理 → 代码分析器”。在任务类型中选择代码分析，即可查看 osTicket 的结构、登录/工单/API 代码位置与文件行号。也可在自动分派模式中直接问 osTicket 问题。详细用法、索引重建和架构见 [代码分析指南](code-analyzer.md)。

## 启动

在项目目录打开 PowerShell，执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --log-config logging.json
```

访问 http://127.0.0.1:8000 。终端保持运行；按 Ctrl+C 停止。如果端口已被占用，换成 `--port 8001`，并访问对应端口。

换一台电脑时，先安装 Python 3.12，再运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
```

项目中的 `.venv` 只用于本机，不能复制到 GitHub。系统默认的 `python` 可能是旧版 Anaconda，所以这里明确使用项目内的 Python。

## 建议按这个顺序体验

1. 点击“核对随身行李”，然后点击“检索政策依据”。阅读回答，展开证据摘要，再打开官方链接核对。
2. 输入“Peach 可以改签吗？”，将票价、退改原因和购票渠道设为“尚未确认”。系统应追问缺少条件。
3. 保留原问题，补充 Standard Plus、个人原因、航司官网，再提交。系统应返回对应的改签摘要。
4. 输入“Peach 航班被取消，能退款吗？”，将原因设为非自愿。系统应返回证据不足；本版没有收录这类规则。
5. 查看“结构化 JSON”，观察状态、reason_code、来源段落、资料版本和延迟。查看“公开资料库”了解收录范围。

这是无会话记忆的接口。追问后请修改原问题或表单，再提交；不要只输入“Standard”作为下一句话。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m evals.run
```

评测报告写入 `evals/latest.json`。固定评测包含故障注入，用于验证 `upstream_error`，不是在正式问答接口里制造假错误。真实知识库故障的演示方式见 `knowledge-maintenance.md`。

## 你最值得先读的代码

- `models.py`：四种状态和响应结构。
- `router.py`：哪些信息缺失时追问、哪些主题必须拒答。
- `service.py`：证据匹配、时效检查、引用和日志。
- `knowledge/peach.json`：如何组织公开政策和来源。
- `evals/cases.json`：哪些回答和拒答行为需要持续保证。

## 当前边界

系统输出的是事先核对过的中文政策摘要，不是模型生成的自由回答。词汇规则只能理解有限表达；对复杂否定句、未收录航司名称或隐含前提，需要继续增加评测和改进。当前测试通过不代表已经达到生产客服准确率。

资料核对日期为 2026-10-26。超过 30 天会要求复核。日期不能为了恢复回答而随意修改，必须先重新阅读官方资料。评测使用固定日期，所以实际界面要求复核时，固定评测仍可能通过，这是有意区分“回归行为”和“当前资料可用性”。

下一步先体验、修改问题、理解状态判断，再扩展评测和接入模型。GitHub 发布与在线部署尚未执行。
